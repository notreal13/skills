# Bitwarden CLI

Работай с хранилищем по принципу минимального доступа. Никогда не раскрывай секреты модели, чату, журналам или файлам.

## Проверить готовность

1. Выполни `command -v bw`. Если команда отсутствует, остановись и предложи установить официальный Bitwarden CLI; не устанавливай его без разрешения пользователя.
2. Определи только значение `status`, не выводя остальные поля: `bw status | sed -E 's/.*"status"[[:space:]]*:[[:space:]]*"([^"]+)".*/\1/'`. Если результат пуст, остановись и сообщи об ошибке без вывода исходного JSON.
3. Если статус `unauthenticated`, попроси пользователя выполнить `bw login` в его Terminal. Не принимай email, мастер-пароль, код 2FA или API-ключ в чате.
4. Если статус `locked` или процесс агента не имеет действующего `BW_SESSION`, выполни процедуру «Передать сессию».
5. Если статус `unlocked`, выполни `bw sync` перед чтением записи.

## Передать сессию

Передавай ключ сессии только в память того процесса, который будет выполнять `bw`. Не проси пользователя вставлять `BW_SESSION` в чат и не сохраняй ключ в обычном файле, конфиге, истории команд или аргументах процесса.

1. Создай отдельный временный каталог через `mktemp -d`, установи права `0700` и запомни полученный абсолютный путь.
2. Создай внутри него FIFO `session.fifo` с правами `0600`.
3. Сразу запусти окончательный shell-процесс с нужными разрешениями. Прочитай одну строку из FIFO в `BW_SESSION`, немедленно удали FIFO и экспортируй переменную только в этом процессе. Не выводи её значение. Зарегистрируй очистку при завершении процесса: выполни `bw lock`, удали `BW_SESSION` из окружения и удали оставшиеся временные объекты.
4. Попроси пользователя выполнить в его Terminal команду ниже, подставив показанный агентом абсолютный путь к FIFO:

   ```bash
   agent_bw_session="$(bw unlock --raw)" \
     && printf '%s\n' "$agent_bw_session" > '<абсолютный-путь>/session.fifo' \
     && unset agent_bw_session
   ```

5. Проверь в том же процессе, что `bw status` показывает `unlocked`, не выводя остальные поля статуса.
6. Удали пустой временный каталог после чтения FIFO.

Не используй для агента `--passwordenv` или `--passwordfile`: они передают мастер-пароль вместо краткоживущего ключа сессии.

## Получить секрет

1. Уточни точное имя или ID записи и нужное поле, если они не указаны.
2. Используй точечную команду: `bw get username`, `bw get password`, `bw get totp` или `bw get item` для одной записи.
3. Если имя неоднозначно, не выполняй массовый вывод записей. Попроси более точное имя или ID. При необходимости выводи только очищенные `id` и `name`, никогда полный JSON записи.
4. Не возвращай пароль, TOTP, ключ, токен или защищённое поле в ответе. Направь секрет без промежуточного вывода:
   - в буфер обмена через `pbcopy` на macOS;
   - в стандартный ввод доверенной команды;
   - в переменную окружения только дочернего доверенного процесса, если программа не поддерживает stdin.
5. Не помещай секрет в аргументы командной строки: они могут быть видны в списке процессов.
6. Сообщи только выполненное действие, имя записи и целевое место без значения секрета.

## Ограничить изменения

- Не выполняй `bw list items` без узкого фильтра и необходимости.
- Не экспортируй хранилище.
- Не создавай, не изменяй, не перемещай и не удаляй записи без отдельного явного запроса пользователя.
- Не передавай секрет недоверенному скрипту, бинарному файлу, сайту или удалённой службе.

## Завершить работу

1. Выполни `bw lock` в процессе с `BW_SESSION`.
2. Удали `BW_SESSION` из окружения и заверши процесс.
3. Удали оставшиеся FIFO и созданный временный каталог по их проверенным абсолютным путям.
4. Выполни `bw status` и подтверди только статус `locked`. Если `bw lock` завершился ошибкой, сообщи об этом без вывода секретных данных.

Сверяй изменившееся поведение CLI с официальной документацией: <https://bitwarden.com/help/cli/>.
